# antislop audit 001, 2026-11-13

Scope: Home dashboard (`frontend/src/views/HomePage.tsx`), app shell spacing (`layout/AppShell.tsx`, `components/PageCenter.tsx`).
Mode: AFTER. Nothing was changed. Verified by reading code and the two screenshots; the page was not clicked through in a browser by me (R-35 open).

Design Read: business overview for directors and managers of a fuel distributor, with a calm data-product language, dial ENERGY 1 / RHYTHM 2 / MOTION 1 (hover plus one entrance).

## HIGH (Hard Gate)

1. **R-25 contrast.** Secondary text uses `text-slate-400` on white (about 2.6:1, needs 4.5:1): the "Keseluruhan" caption on every KPI tile, the "Data" coverage chip text at 11px, the overall-value note under the breakdown, and the map hint. Fix: `text-slate-600` for captions.
2. **R-17 / R-38 number without its unit.** The Total Volume tile reads `4,996,168` with no unit, because the label drops "(KL)". The briefing also says "243.392 unit". A volume without KL misleads a director. Fix: carry the metric `unit` to the payload and show it beside the value; tell the briefing prompt to use it.
3. **R-02 em dash.** `format()` in HomePage returns `—` for a missing value (also `formatBusinessValue` in `lib/businessPresentation.ts`). Fix: "Tidak tersedia".
4. **R-39 accessible name / affordance.** The whole KPI tile is a link whose accessible name is the full tile text plus an arrow; it needs a clear name ("Buka tren Tingkat Keterlambatan di Ask Data"), `cursor: pointer` is not set in the base layer for buttons, and the sparkline `aria-hidden` hides the only trend cue from screen readers (add the change text, already present, to the name). Fix in base CSS plus `aria-label`.
5. **R-35 not verified in a browser.** Click-through of tiles, question chips, search box, refresh, retry, mobile width and the map is only covered by mocked tests. Fix: run it on CAI and record the list.

## MEDIUM (Purpose-Gate)

6. **R-05 / R-14 scorecard balance (your point 1).** Three equal tiles in a 4-column grid leave an empty fourth slot; all tiles carry the same weight although KPI 1 is the headline; the change chip wraps to two lines ("-0.2 / poin"); values use a dot decimal (`16.1%`, `4,996,168`) while the briefing uses Indonesian commas (`15,6`). Fix: grid columns follow the KPI count (3 tiles fill the row), the headline tile larger, chip on one line, one locale for all figures.
7. **R-04 generic icon.** Sparkles on the search box and the briefing header. Fix: no icon on the search box; a plain label on the briefing.
8. **R-08 decorative arrow.** An arrow on every KPI tile. The tile is already a link; the arrow adds nothing. Fix: remove it, keep the hover state.
9. **R-06 uppercase labels with tracking** on KPI labels (`uppercase tracking-wide`). Fix: sentence case, semibold.
10. **R-19 / your point 2, entrance motion.** Sections pop in one by one as each request answers (tiles, briefing, charts), shifting the page. Fix: reserve the layout while loading and give each section one short fade and rise on arrival (200 ms, staggered at most 3 steps), off under `prefers-reduced-motion`. Purpose: stop the layout jump and show what arrived.
11. **R-27 loading state names nothing.** One pulsing sentence. Fix: a placeholder in the shape of the real layout (tiles, briefing, two cards) with what is loading named once.
12. **R-12 / R-01** soft shadow on every card and a violet-to-orange gradient behind the briefing title. Fix: flat card with a border for Home; the gradient goes unless you want it as the one accent.

## LOW (Quality Locks)

13. **R-29 palette.** Orange accent, navy, violet icon, slate, and the grey-blue bars: the violet map icon is a third accent. Fix: use orange and navy only.
14. **Spacing, your point 3 (R-20 consistency).** The page sits inside `main` padding (24px) plus its own `px-8` plus a centered `max-w-7xl` (1280px). On a 1929px screen that leaves about 330px empty on each side next to the sidebar. Other pages use `PageCenter` (`max-w-7xl px-4 py-8`) inside the same `main` padding, so they have the same gap. Fix once for every feature: `main` padding `p-3 sm:p-4`, `PageCenter` and Home to `max-w-[1680px]` with `px-2 sm:px-4`.

## Performance note (your point 2, load time; not a slop rule)

Cold, `/home` runs about 15 Trino queries (3 KPIs by month with their overall value and coverage, a breakdown, a map) plus the briefing model call after them: roughly 10 to 25 seconds the first time, under 1 second after, because it is kept 15 minutes in memory. It is lost at every Backend restart or deploy, and the briefing only starts after the figures. Fix: keep Home in the answer-cache disk store (survives restarts), warm it on start and after a model publish, serve the last result at once while refreshing, start the briefing without waiting, and keep the last payload in the browser so returning to Home is instant.
